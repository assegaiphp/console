# Assegai Console 0.10.5

Draft release notes. This release has not been published.

Console 0.10.5 fixes CLI version reporting when global and project-local Console installations are loaded in the same process.

## Correct CLI installation identity

A global Console 0.10.4 running inside a project containing Console 0.10.3 could report `0.10.3` from `assegai version` or `assegai info`, while `assegai --version` reported `0.10.4`.

Version reporting now selects Composer metadata belonging to the Console installation whose code is executing. Loading a project's autoloader before or after CLI startup cannot substitute another installation's version. The same identity supplies update checks and framework release recommendations.

Checkout and Composer dependency entrypoints remain supported, including Composer binary proxies and symlinked installation paths. If metadata for the executing installation is unavailable, the CLI reports `Unknown` rather than borrowing a version from another copy.

## Compatibility

PHP 8.4+ and the existing Composer requirements remain unchanged. Dependency constraints and installation locations are unchanged. This correction does not update a separate Console executable selected by a shell alias, wrapper, or `PATH`; installation selection must be verified separately when both version commands agree on an older version.

After publication, an existing global installation can be updated with `assegai global update` or `assegai -g update`.

## Validation

The full suite passed on macOS with PHP 8.4.21 and 8.5.11: 217 tests, 1,014 assertions, and one existing skip. PHPStan level 8 and strict Composer validation passed. Regression coverage includes both autoload orders, checkout and dependency entrypoints, binary proxies, custom vendor directories, symlinked paths, and missing installation metadata. Linux, Windows, and Hostinger validation remain pending.
