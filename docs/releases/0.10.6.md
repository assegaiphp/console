# Assegai Console 0.10.6

Console 0.10.6 adds independent Web Component groups, improves watch-mode lifecycle handling, and isolates extension discovery from older project-local Console installations.

## Independent Web Component bundles

Define groups in `assegai.json` to build site components separately from editor or other application components:

```json
{
  "webComponents": {
    "groups": {
      "site": {
        "sources": ["src/WebComponents/Site"],
        "output": "public/js/site.min.js"
      },
      "editor": {
        "sources": ["src/WebComponents/Editor"],
        "output": "public/js/editor.min.js"
      }
    }
  }
}
```

Build, list or watch selected groups:

```bash
assegai wc:build --group=site
assegai wc:list --group=editor --json
assegai wc:watch --group=site --group=editor
```

`--group` is repeatable. Omitting it selects all configured groups. Sources are explicit workspace-relative directories or `.wc.ts` files; glob patterns are not supported. Once groups are configured, components outside their source paths are excluded from discovery.

Each group has its own entry file, component manifest and esbuild dependency graph under `.cache/assegai/groups/<name>/`. The graph, `esbuild-meta.json`, records transitive inputs and emitted outputs. Building a selected group leaves unselected groups' artifacts unchanged.

Group source memberships cannot overlap. Unknown groups, conflicting artifact paths and paths escaping the workspace are rejected. Importing another group's `.wc.ts` component is rejected; shared ordinary TypeScript and CSS dependencies remain supported.

Each group owns its JavaScript output and the sibling CSS output emitted by esbuild. A previously emitted group stylesheet is removed when a successful build no longer emits it. Applications remain responsible for including the bundles their pages need. Compiler/runtime builds and deployment uploads remain separate workflows.

## Watch and hot reload

Watch mode detects component additions, removals and renames, including the first component in an initially absent source directory. Empty watch sessions now stay active instead of exiting immediately. Missing or removed directories are handled without filesystem warnings; unreadable existing directories now raise their filesystem error instead of being silently ignored.

Esbuild watches dependency content changes. Component membership checks use the configured hot-reload polling interval and the existing watch tick. With the default interval, membership detection takes approximately one second, followed by build and browser-reload time. Idle membership checks do not read source contents or hash bundles.

Successful builds update separate group reload markers and the existing root marker. CSS-only output changes also update the reload version. `--no-hot-reload` keeps watch builds and membership detection active without writing browser markers.

One watch session coordinates its selected groups, stops its child processes together and deactivates reload markers on shutdown. Locks prevent concurrent writers to the same group; a different group can still be built independently. `assegai serve --dev` watches all configured groups.

## CLI isolation and entrypoint

Extension discovery keeps the executing Console installation's classes authoritative after loading a workspace autoloader and before parsing package manifests. An older project-local Console can no longer substitute incompatible classes during discovery or subsequent commands. Other dependency namespaces retain their existing loader priority.

The CLI entrypoint also explicitly forwards the application's return code if automatic exit has been disabled. Symfony's default automatic exit behavior is unchanged; failed commands already returned a nonzero status in previous releases.

## Compatibility and upgrade

PHP 8.4+ and the existing Composer dependency requirements are unchanged. Existing projects without `webComponents.groups` retain their single-bundle source discovery, output paths and list JSON structure. Grouped JSON results additionally identify each component's group. No framework request-time code changes are required.

Update an existing global installation and verify its version:

```bash
assegai global update
assegai --version
```

`assegai -g update` is the equivalent shorthand. Groups are opt-in and require no migration for existing single-bundle projects. Watch workflows should account for empty sessions remaining active.

## Validation

CI passed on Ubuntu 24.04 with PHP 8.4.26 and 8.5.11. Each full suite reported 233 passing tests, 1,073 assertions and one existing explicitly skipped test. PHPStan level 8 and strict Composer validation passed.

Regression coverage includes selected-group isolation, invalid ownership and paths, additions/removals/renames, initially empty sources, CSS-only changes, reload markers, process teardown, CLI exit statuses and older workspace Console installations during extension discovery. Console orchestration tests use fake esbuild; real-esbuild group isolation was checked separately. Focused local checks also ran on macOS. Windows was not tested.
