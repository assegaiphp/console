# Assegai Console 0.10.0

Assegai Console 0.10.0 aligns new-project and update workflows with the AssegaiPHP 0.10 framework milestone: configurable authentication failure handling and a complete exception-filter lifecycle.

## New projects

- new projects require `assegaiphp/core:^0.10.0`
- the recommended ORM constraint follows the same 0.10 release line
- scaffolds include `config/auth.php` for login-redirect policy and framework-owned session settings
- `config/default.php` remains focused on general shared application configuration
- `config/secure.php` remains the place for database credentials, auth secrets, and sensitive overrides

## Updates

`assegai update` aligns directly installed 0.9-line repositories participating in this coordinated release:

- Core
- ORM
- Auth
- Collections
- Common
- Forms
- Util
- Validation

Queue drivers and Events are not forced onto 0.10 by this milestone. They retain their independently published constraints and are included in Composer updates only according to their own compatibility lines.

Existing applications may keep session settings in `config/default.php`. To register Core's `LoginRedirectFilter` by class name, add `config/auth.php`, configure the application-owned login URL, and apply the filter only to browser controllers that should redirect.

## Compatibility

- Console now requires `assegaiphp/common:^0.10.0`.
- The fallback framework recommendation is `^0.10.0`.
- Semantic CLI versions continue to derive their matching minor release line.

## Validation

Release coverage verifies new-project Core and ORM constraints, dedicated auth configuration defaults, update behavior for direct first-party dependencies, and preservation of independently versioned packages.
