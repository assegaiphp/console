# Assegai Console 0.11.0

Console 0.11.0 uses Core 0.11 as the baseline for new projects and project updates. It replaces automatic CLI-minor-based dependency recommendations with explicit compatible requirements for each managed first-party package.

## New project baseline

`assegai new` now creates projects requiring `assegaiphp/core:^0.11.0`. The bundled Composer template and the shared project-default loader use the same requirement.

PHP 8.4+ remains required. Console's own dependency requirements are unchanged.

## Independent package recommendations

Core and Console use the 0.11 release line. ORM, Events, Auth, Collections, Forms, Util and Validation retain their compatible published 0.10 lines; Common uses `^0.10.1`.

`assegai add` and `assegai update` share the managed package recommendations. Adding a managed companion package now selects its supported constraint instead of an unrestricted wildcard. Other first-party package names remain accepted. Existing RabbitMQ and Beanstalkd constraints remain independent of the Core release line.

Project updates no longer force every managed package onto the target Core minor version. For example, a project can update Core to `^0.11.0` while retaining ORM `^0.10.2` and Events `^0.10.0`. Existing newer constraints are not downgraded.

Default recommendations no longer depend on Composer version metadata for the running CLI. CLI version reporting and self-update checks still identify the executing Console installation.

## Upgrade an existing project

Update the globally installed CLI and inspect the project migration before applying it:

```bash
assegai global update
assegai --version
assegai update --to=0.11 --dry-run
assegai update --to=0.11
```

`assegai -g update` is the equivalent global-update shorthand. The dry run lists requirement changes without modifying files or dependencies. Cross-release changes still require confirmation; non-interactive updates require an explicit `--yes` after reviewing the plan.

Console 0.11 manages the Core 0.11 line and no longer accepts `--to=0.10`. Keep a Console release supporting Core 0.10 for maintenance of projects that must remain on that line. The update command does not downgrade projects.

If the project also requires Console, its requirement is updated alongside Core in the same Composer operation. Compatible companion packages use their own release lines, including requirements under `require-dev`.

The update preserves its existing safety boundaries: application PHP source is not rewritten, manifests are restored if Composer fails, and `vendor/` may require `composer install` after a failed dependency operation. Commit or back up the project before upgrading and run the application's tests afterward.
