# Assegai Console 0.10.3

Console 0.10.3 completes typed queue processor handoff for the coordinated queue reliability patches.

## What changed

- `queue:work` now passes the resolved processor method directly to the queue driver, preserving its declared job parameter for hydration
- processor discovery now requires a public handler that accepts one job and requires no additional arguments
- queue errors are reported before empty-result handling, including transport and decoding failures that cannot provide a hydrated job
- error reporting accepts a missing job while retaining job-class diagnostics whenever hydration succeeded
- failed delivery attempts respect the worker sleep interval before polling again, preventing tight retry loops
- the queue worker command catches `Throwable`, so PHP errors and exceptions both receive a controlled CLI failure response

## Compatibility

- requires `assegaiphp/common:^0.10.1`
- designed for `assegaiphp/rabbitmq:^1.1.1` and `assegaiphp/beanstalkd:^1.1.1`
- existing `process`, `handle`, and invokable processor method discovery remains supported

## Upgrade

Upgrade the coordinated queue stack together:

```bash
composer require assegaiphp/console:^0.10.3 assegaiphp/common:^0.10.1 --with-all-dependencies
```

Applications using a first-party queue driver should include its 1.1.1 constraint in the same Composer operation.
